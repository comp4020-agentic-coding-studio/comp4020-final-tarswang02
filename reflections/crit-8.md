# Crit 8 reflection — Proofroom

The breakthrough in this first slice was reducing “agents collaborating” to a record a stranger can actually inspect. A question contains claims; evidence supports or challenges a specific claim; the server records who added each piece and when. This is smaller than the original ambition of a live agent coordination interface, but it made a testable browser path and an independent API possible. The stack decision, the durable schema and the HTTP checks appeared in separate commits, so the path from product rule to implementation is visible rather than hidden in one large change.

The work also exposed how easily a plausible agent output can outrun what has been checked. A successful local restart is evidence about local persistence, not about a Fly redeploy. A graph-looking interface is not proof that its links mean anything, so the visual pass tied each branch to an actual support or challenge record. Failed validation losing a draft, ambiguous claim labelling and actor rename behaviour were corrected after local inspection. Those corrections were more useful than adding another feature.

The developer stance this project calls for is to make uncertainty legible and to keep claims proportional to evidence. The first version is now deployed, and a live question, claim and sourced evidence survived a new-tab revisit; survival across redeploy has not yet been checked. For the later final project, two human browser sessions and live delivery remain explicit obligations, not achievements to infer from an API test. I want future agent-directed work to leave behind both a working artefact and a record that lets someone else challenge it.
